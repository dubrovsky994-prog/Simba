### Решение

Отдельный DEV-маршрут `/owner` в main.tsx, lazy import всего модуля. Публичный App не монтируется на этом маршруте, поэтому его аналитика и захват UTM не запускаются. Production-сборка исключает код и хранилище owner; одного скрытого адреса или пароля на клиенте недостаточно для защиты.

Данные записываются только при явном действии. localStorage — рабочее хранилище на одном устройстве, JSON — переносимая резервная копия. Демо и личные данные имеют отдельные ключи. Не загружаются реальные сведения из переписок, API лидов или других проектов. Внешние шрифты и существующие публичные ассеты могут загружаться, но записи кабинета в эти запросы не включаются.

Альтернативы: встраивание в HomePage создаёт связь с публичным лендингом; отдельный backend с auth нужен для онлайна, но сейчас требует выбора провайдера и способа входа. Локальный MVP позволяет проверить рабочие сценарии до этих решений. Цена выбора — отсутствие синхронизации, доступа с другого устройства и настоящего AI.

### Структура

- model.ts: сущности, даты, расчёт показателей, отдельные демонстрационные примеры.
- repository.ts: контракт хранения, проверка формата/версии, защита от устаревших записей, экспортируемый parser.
- modules.ts: реестр семи разделов и шести будущих модулей.
- OwnerApp.tsx: композиция блоков и пользовательские действия.
- RecordEditor.tsx: доступная модальная форма с валидацией, включая навыки проекта.
- SkillEditor.tsx: ручное добавление и уточнение навыков владельца.
- owner.css: стили внутри `.owner`; публичные компоненты и глобальные стили не меняются.
- tests/owner.test.mjs: расчёты и пограничные сценарии хранения, без установки новых зависимостей (esbuild из текущего Vite lockfile).

### Что работает

1. Сегодня: дата, сохраняемый фокус, счётчики.
2. Требует решения: создание, изменение, одобрение, отклонение, перенос на завтра, возврат, фильтры, история до 1 000 событий. Отложенное решение возвращается в очередь в день срока; дата пересчитывается раз в минуту открытой страницы.
3. Business Pulse: вручную введённые суммы по проектам за всё время, положительный остаток до бюджета, открытые/заблокированные/просроченные/завершённые проекты. Нет фиктивных трендов, конверсий или банковской интеграции.
4. Проекты: создание/редактирование, статус, следующий шаг, срок, процент готовности, бюджет/получено, поиск и фильтр. При завершении готовность становится 100%.
5. Tactical Opportunities: гипотеза/наблюдаемый факт, источник, дата, маленький тест, создание связанного проекта одним действием без повторного создания, архив и восстановление.
6. Tactical Opportunities: отдельный экран сигналов и небольших проверок.
7. SIMBA AI: компактно присутствует на экране «Сегодня», показывает аналитику и последние действия; полный журнал администратора и локальная сводка открываются отдельно. Не LLM-чат и не автономный исполнитель.
8. Skill Box: отдельная личная библиотека навыков со статусом, назначением и проектами-источниками. При сохранении проекта значения из поля «Навыки и решения проекта» автоматически объединяются с библиотекой без дублей.

На узком экране всегда открыт только один раздел. Нижнее меню содержит «Сегодня», «Решения», «Проекты», «Скиллы» и «Ещё»; внутри «Ещё» находятся Business Pulse, Tactical Opportunities и SIMBA AI. Адрес раздела сохраняется в hash, поэтому работают обновление страницы и кнопки назад/вперёд.

### Хранение и восстановление

Ключи: `simba.owner.v1.personal`, `simba.owner.v1.demo`. Очистка данных браузера удалит записи: используйте «Скачать копию». Импорт проверяет формат, версии, уникальность ID, даты, диапазоны и размер до 2 МБ; замена требует подтверждения в интерфейсе. Повреждённое содержимое не стирается автоматически и доступно для скачивания. Восстановление корректной копии может заменить его после подтверждения. При изменении записи в другой вкладке устаревшее сохранение отклоняется: обновите страницу и повторите изменение. Это защита от обычных устаревших вкладок, а не транзакционная многопользовательская база.

### Следующая архитектурная ступень

OPEN: провайдер размещения/БД, способ входа владельца, хранение персональных данных, AI-провайдер/ключ/бюджет.

Перед онлайн-доступом: серверная сессия с HttpOnly/Secure/SameSite cookie, проверка роли owner на каждом API, защита изменений от CSRF, валидация на сервере, версии записей/конфликты, резервное копирование и проверка восстановления. Только после этого заменять DEV-ограничение; клиентский флаг не является авторизацией.

Для сетевого репозитория потребуется асинхронный controller/hook с loading/error состояниями вместо синхронного localRepository. UI и модель данных остаются отдельными. Расширения:

| Модуль | Будущие данные / связь |
|---|---|
| Sales | Сделки, этапы, привязка к проекту |
| Execution Control | Задачи, исполнитель, попытки, артефакты, явные разрешения |
| Finance | Платежи/счета, даты и валюты; не смешивать с текущими ручными итогами |
| Leads Radar | Входящие сигналы, источник/дата, отдельный защищённый API |
| Product Lab | Эксперименты из opportunities, критерии успеха и результат |
| Decision Journal | Текущая история + серверный журнал автора/контекста/результата |

## Проверка

`npm.cmd run build`

`node --test tests/owner.test.mjs`

`npx.cmd eslint src/main.tsx src/owner tests/owner.test.mjs`

Общий `npm.cmd run lint` имеет две исходные ошибки в simba-agent-bridge: prefer-const в src/github/tree.ts:25 и unused _next в src/index.ts:49. Они существовали до MVP и не относятся к нему.

Для smoke-проверки: личное пустое состояние → демо → создать/изменить проект и указать навыки → проверить автоматическое появление без дублей в Skill Box → решение одобрить/перенести/вернуть → возможность с источником → связанный проект → архив/восстановление → копия/импорт → перезагрузить → убедиться, что личные данные отделены. Проверить переходы нижнего меню при 390 px и бокового меню на desktop, отдельный экран для каждого раздела, кнопки назад/вперёд, клавиатуру/Escape в диалоге и отсутствие ошибок консоли. На production preview `/owner` не должен показывать записи; `/`, `/privacy`, `/audit` должны сохранять исходное поведение. Внешние формы заявок при smoke-проверке не отправлять.
